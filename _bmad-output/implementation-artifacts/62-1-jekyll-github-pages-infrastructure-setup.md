Status: done

## Story

As a project maintainer,
I want a Jekyll-based GitHub Pages documentation site with Just the Docs theme, search, and CI/CD deployment,
so that all project documentation is published as a searchable, navigable website that auto-deploys on push to main.

9. `bundle exec jekyll build` succeeds with zero errors

## Dev Notes

### Limitations (Deferred Items)

1. **Search init (AC #6):** `bundle exec just-the-docs rake search:init` requires Ruby 3.3+. Local machine has Ruby 2.6.10 (macOS system Ruby). The GitHub Actions CI uses Ruby 3.3 and will generate the search index on first build. Just the Docs v0.12.0 supports client-side lunr.js search which regenerates the index on every build automatically.
2. **Build verification (AC #9):** `bundle exec jekyll build` cannot be verified locally due to Ruby version constraint. CI will validate on first push.
3. **Gemfile.lock:** Not committed. CI generates it fresh per build. For reproducibility, the lockfile should be generated once (on a machine with Ruby 3.3+) and committed in a follow-up.
4. **`bundle audit`:** Cannot run locally due to Ruby version. CI or a machine with Ruby 3.3+ should verify no known vulnerabilities.

### Critical Decision: Site Directory Location

**Decision: Place site in `docs/` directory at project root.**

Rationale:
- GitHub Pages can deploy from `/docs` on main branch OR via GitHub Actions
- Existing `docs/` directory already has 38 markdown files — these become the seed content
- Using GitHub Actions workflow (not branch-based deploy) gives more control
- The `_config.yml` goes in `docs/` root, existing markdown files get front matter added later
- Alternative (`site/` directory) would duplicate content — `docs/` is cleaner

**IMPORTANT:** The existing `docs/index.md` (master table of contents) was REPLACED by the new landing page.

### Navigation Front Matter Pattern

Top-level parent pages use `has_children: true`. Child pages reference their `parent`. Grandchildren add `grand_parent`.

Example hierarchy:
```yaml
# docs/plugins/index.md
---
title: Plugins
nav_order: 4
has_children: true
---

# docs/plugins/agents/index.md (or agents/claude-code.md)
---
title: Agent Plugins
nav_order: 2
parent: Plugins
has_children: true
---

# docs/plugins/agents/claude-code.md
---
title: Claude Code
nav_order: 1
parent: Agent Plugins
grand_parent: Plugins
---
```
